## 4. Medición de rendimiento y decisiones técnicas

El equipo midió cuatro operaciones en un entorno local con 30 ejecuciones por operación. Los tiempos corresponden a la capa de servicios PHP.

| Operación | Mediana (ms) |
| --- | ---: |
| Tablero con consulta directa a MongoDB | 2,233 |
| Tablero con lectura desde Redis (`HIT`) | 1,420 |
| Listado de socios en MongoDB | 0,323 |
| Consulta de membresías en MongoDB | 0,321 |

En esa ejecución, Redis redujo un **36,40 %** la mediana del tiempo de consulta del tablero. La metodología y las muestras se registran en [mediciones-S3.md](../mediciones-S3.md) y se pueden reproducir con [benchmark-s3.php](../../scripts/benchmark-s3.php).

GymFlow mantiene MongoDB como fuente principal de datos y usa Redis para almacenar temporalmente los indicadores de cada gimnasio. La caché tiene un tiempo de vida de 60 segundos en la configuración de referencia. Cuando Redis deja de responder, el tablero consulta MongoDB directamente. El diseño está descrito en [arquitectura-v1.md](../arquitectura/arquitectura-v1.md).
